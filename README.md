# Мониторинг системы

Сервер на C++20 собирает системные метрики Linux и раз в секунду отправляет один и тот же снимок всем подключённым WebSocket-клиентам. Для работы с сетью используются Boost.Asio и Boost.Beast. В каталоге `www/` есть страница с текущими значениями и графиком, а также страница для проверки множества одновременных подключений.

## Возможности

- Загрузка CPU по разнице показаний `/proc/stat` между двумя измерениями.
- Использование памяти по `MemTotal` и `MemAvailable` из `/proc/meminfo`.
- Загрузка GPU из `/sys/class/drm/card*/device/gpu_busy_percent`; если этот показатель недоступен, используется `nvidia-smi`. Если оба источника недоступны, передаётся `0`.
- Рассылка JSON-сообщений всем подключённым клиентам через WebSocket.

При первом измерении загрузка CPU равна `0`: для расчёта нужна пара последовательных показаний.

## Требования

- Linux с доступом к `/proc/stat` и `/proc/meminfo`.
- Компилятор с поддержкой C++20.
- CMake 3.20 или новее.
- Boost 1.74 или новее, включая компонент `system`.
- `nlohmann_json` с CMake-конфигурацией и библиотека потоков.
- Необязательно: `nvidia-smi` для получения загрузки GPU на поддерживаемых устройствах NVIDIA.

## Сборка и запуск

Из корня проекта выполните:

```bash
cmake -S . -B build
cmake --build build
./build/monitoring_server
```

Сервер слушает `0.0.0.0:8080`. Для локального подключения используйте `ws://127.0.0.1:8080`. Адрес и порт заданы в `src/main.cpp`; аргументов командной строки для их изменения сейчас нет. Чтобы остановить сервер, нажмите Enter в терминале, где он запущен.

### Веб-интерфейс

Сервер принимает WebSocket-подключения и не раздаёт HTML-файлы. В другом терминале запустите статический сервер:

```bash
python3 -m http.server 8000 --directory www
```

Откройте [http://127.0.0.1:8000/](http://127.0.0.1:8000/) для просмотра метрик или [http://127.0.0.1:8000/load-test.html](http://127.0.0.1:8000/load-test.html) для проверки одновременных подключений. Обе страницы подключаются к WebSocket на порту `8080` того же хоста, с которого они открыты. Если запускаете интерфейс на другом компьютере, откройте его через адрес машины с запущенным сервером.

## Формат сообщений

Сервер отправляет текстовый JSON примерно раз в секунду:

```json
{
  "type": "metric",
  "version": 1,
  "timestamp_ms": 1730000000000,
  "data": {
    "cpu": { "total_percent": 24.5 },
    "gpu": { "total_percent": 12.0 },
    "memory": { "used_mb": 4096.0, "percent": 50.0 }
  }
}
```

`timestamp_ms` — время сбора данных в миллисекундах с начала эпохи Unix. Значения `total_percent` и `percent` выражены в процентах, `used_mb` — в МиБ (1024² байт). При подключении клиент получает следующий периодический снимок. Сообщения от клиентов сервер читает, но не обрабатывает.

## Структура проекта

| Путь | Назначение |
| --- | --- |
| `src/main.cpp` | Запуск и остановка сервера |
| `src/server.cpp`, `src/session.cpp` | Приём подключений и WebSocket-сессии |
| `src/monitoring/` | Сбор метрик, периодическая рассылка и учёт клиентов |
| `include/` | Заголовочные файлы |
| `www/index.html` | Панель мониторинга |
| `www/load-test.html` | Страница для создания множества WebSocket-подключений |

Сбор метрик выполняется один раз за интервал, после чего готовое сообщение рассылается всем клиентам. У каждой сессии есть небольшая очередь отправки: если клиент не успевает принимать данные, устаревшие ожидающие снимки отбрасываются.
